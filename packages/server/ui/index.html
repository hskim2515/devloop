심각도프로젝트제안파일확신

      
분석 실행을 누르면 AI 가 최근 리포트·커밋·코드를 읽고 고칠 점을 찾습니다 (5분 안팎, Claude 비용 발생)

    


    
    

      
AI 가 고친 소스 상태는 원격에 올리지 않아도 키트가 버전으로 갖고 있습니다(키트 저장소 태그 devloop/v{n}). 버전마다 프론트+백엔드+DB 사본을 띄워 접속해 보고, 마음에 들면 원격으로 보냅니다(브랜치만 / PR·MR / 자동 병합).

      
미리보기 레시피 
        
프론트 빌드·백엔드 실행·DB 복제 방법. 자리표시자 {base} {project} {n} {db} {port} {host} {previewUrl} {backUrl}. db.mode: template(기본, 템플릿 DB 에서 초 단위 복제) · clone(매번 라이브에서, 느림) · shared(사본 없이 개발 DB 공유). maxUp(동시 개수, 기본 1) · volumes '호스트:컨테이너[:ro|:shared]'(표시 없으면 샌드박스 사본) · ttlHours(미사용 자동 중지, 기본 12)

        
        

      

      
샌드박스 사본 
미리보기는 원본 파일 저장소 대신 이 사본을 씁니다(레시피 volumes 중 :ro·:shared 표시가 없는 것). 미리보기에서 만든 파일은 여기 쌓이고, 원본에 새로 올라온 자료는 초기화해야 들어옵니다.

진행 로그

      

    


    
    

      
배포판은 어느 버전의 소스를 받는 쪽에 그대로 넘길 수 있게 묶은 한 덩이입니다 — 프론트 빌드 결과·백엔드 실행 파일·릴리스 노트에 DB 스키마를 맞추는 DDL 까지. git 은 소스를 추적하지만 DB 스키마는 아무도 추적하지 않아, 받는 쪽에 테이블·열이 없어 배포 직후 깨지는 일을 막습니다. 빌드 방법은 버전 탭의 미리보기 레시피를 그대로 씁니다.


      

        
기준 스냅샷 (받는 쪽 DB) 

        
DDL 은 받는 쪽에 없는 것만 담습니다. 그러려면 받는 쪽 DB 의 스키마를 한 번 알려줘야 합니다 — 아래 SQL 을 받아 그 DB 에 돌리고(읽기만 합니다) 나온 파일을 올리세요. 올리지 않으면 직전 배포판의 스냅샷을 쓰고, 그것도 없으면 전체 스키마를 만드는 DDL 이 나옵니다.

        

          
          
          
          
          
        

      


      
빌드 명령 

        
미리보기 레시피의 명령을 그대로 쓰되, 프로젝트 설정 release.front.build·release.back.build 를 적으면 그것으로 빌드합니다. 미리보기는 개발용 프로파일로 빌드합니다 — 운영에 넘길 배포판이면 운영 프로파일 명령을 적어 주세요(예: 프론트 --mode product, 백엔드 -Pprofile=product).

#제목라벨작성

    

    
    

      
로드맵은 기능들을 마일스톤별로 묶어 진행률을 봅니다. 진행률은 기능 상태와 묶인 작업의 병합 비율로 어림합니다. 원격 저장소에 새 커밋이 올라와 어느 기능의 코드 범위가 바뀌면 원격 변경 으로 표시되고 알림이 갑니다(지식 탭의 원격 감시 주기).

      

      

        
        
        
        

      

      

    

    
    

      
기능은 로드맵과 작업의 관리 단위입니다. 기능마다 코드 범위(지식 그래프의 화면·메뉴·기능 노드 + 이어진 파일, 직접 적은 파일)를 두면 그 기능의 작업이 그 코드부터 보고, 어떤 수정이 어느 기능에 영향 주는지 보입니다. 작업의 인수 조건이 통과하면 기능에 쌓여 회귀 검증 재료가 됩니다.

            · 보관만 - 키트 저장소 안에만 둡니다. 원격(GitHub/GitLab)엔 아무것도 안 생깁니다. 콘솔 버전 탭에서 미리보기로 확인한 뒤 내보내기.

            · 브랜치 푸시만 - 그 작업 브랜치를 원격에 올립니다. PR/MR 은 안 만듭니다. 팀원이 브랜치를 받아 직접 검토·병합할 때.

            · PR 까지 - 브랜치를 올리고 기준 브랜치로 향하는 PR/MR 을 만듭니다. 병합은 사람이.

            · 자동 병합 - PR 을 만든 뒤 기준 브랜치와 합쳐 재검증하고 통과하면 병합, 배포까지 추적합니다.
